# 英语教学管理平台实战开发（13）：实现角色新增、编辑与启停用

## 一、前言

第12篇已经完成角色数据模型、Seed 初始化和角色列表页面。现在可以看到系统管理员、教务人员、教师、家长等角色，以及每个角色关联的用户数量。

但目前角色还只能查看，不能维护。

本篇继续完善角色管理，实现三个功能：

1. 新增自定义角色。
2. 编辑角色名称和说明。
3. 启用或停用角色。

这里先明确一个设计原则：角色编码是系统内部使用的稳定标识，不应该在编辑时随意修改；系统内置角色也不能被普通操作停用。

例如 `ADMIN`、`TEACHER` 这样的编码，后续可能被权限判断、初始化数据和业务代码引用。如果允许随意修改，角色名称虽然变了，系统内部的关联规则却可能失效。

因此，本篇采用以下规则：

| 操作    | 自定义角色  | 系统角色        |
| ----- | ------ | ----------- |
| 新增    | 支持     | 不允许手动新增系统角色 |
| 修改名称  | 支持     | 支持          |
| 修改说明  | 支持     | 支持          |
| 修改编码  | 不允许    | 不允许         |
| 启用/停用 | 支持     | 不允许停用       |
| 删除    | 本篇暂不实现 | 本篇暂不实现      |

本篇继续沿用项目现有的 Next.js Server Actions、Zod、Prisma Service 和 shadcn/ui 组件结构。

## 二、完善角色数据模型

第12篇已经建立了 `Role` 模型，现在需要增加角色启用状态。

打开 `prisma/schema.prisma`，在现有 `Role` 模型中增加：

```
model Role {
  id          String   @id @default(cuid())
  code        String   @unique
  name        String
  description String?
  isSystem    Boolean  @default(false)

  // 新增：角色是否启用
  isActive    Boolean  @default(true)

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  userRoles   UserRole[]

  @@index([name])
}
```

`isActive` 用来控制角色是否可用。

这里不直接删除停用角色，因为角色可能已经分配给用户。停用和删除是两种不同的业务行为：

- 停用：保留角色及关联关系，但后续不再允许其参与授权。
- 删除：需要考虑用户关联、权限关联以及历史数据。

本篇先实现停用，后续权限校验章节再让这个状态真正影响用户访问权限。

## 三、定义角色表单校验规则

创建或修改角色时，需要校验角色编码、名称和说明。

打开 `features/roles/schemas.ts`，保留原来的列表查询 Schema，并增加：

```
import { z } from "zod";

export const roleListQuerySchema = z.object({
  page: z.coerce.number().int().min(1).catch(1),
  keyword: z.string().trim().max(50).catch(""),
});

const roleCodeField = z
  .string()
  .trim()
  .min(2, "角色编码至少 2 位")
  .max(30, "角色编码不能超过 30 位")
  .regex(
    /^[A-Z][A-Z0-9_]*$/,
    "角色编码必须以大写字母开头，只能包含大写字母、数字和下划线"
  );

const roleNameField = z
  .string()
  .trim()
  .min(1, "请输入角色名称")
  .max(50, "角色名称不能超过 50 位");

const roleDescriptionField = z
  .string()
  .trim()
  .max(200, "角色说明不能超过 200 位")
  .transform((value) => value || null);

export const createRoleSchema = z.object({
  code: roleCodeField,
  name: roleNameField,
  description: roleDescriptionField,
});

export const updateRoleSchema = z.object({
  name: roleNameField,
  description: roleDescriptionField,
});

export type CreateRoleInput = z.infer<typeof createRoleSchema>;
export type UpdateRoleInput = z.infer<typeof updateRoleSchema>;

export type RoleFormState = {
  message?: string;
  fieldErrors?: {
    code?: string[];
    name?: string[];
    description?: string[];
  };
  values?: {
    code?: string;
    name?: string;
    description?: string;
  };
};
```

这里将新增和编辑分成两个 Schema。

新增时需要填写角色编码；编辑时不允许修改角色编码。

这样不是单纯为了表单方便，而是将业务规则放到了服务端校验层，不能依赖前端隐藏输入框来保证数据安全。

## 四、实现角色 Service

创建和编辑角色都属于数据库写入操作，因此放在 `features/roles/service.ts` 中。

保留原来的 `getRoleList`，在文件中增加以下代码。

### 4.1 定义操作结果

```
export type RoleOperationResult =
  | { success: true }
  | {
      success: false;
      code: "NOT_FOUND" | "CODE_TAKEN" | "SYSTEM_ROLE";
      message: string;
    };

function getErrorCode(error: unknown): string | undefined {
  if (
    typeof error === "object" &&
    error !== null &&
    "code" in error
  ) {
    const code = (error as { code?: unknown }).code;

    return typeof code === "string" ? code : undefined;
  }

  return undefined;
}
```

数据库操作可能出现角色不存在、编码重复等情况。这里将这些业务结果统一返回给 Action，而不是把 Prisma 异常直接暴露给页面。

### 4.2 实现角色详情查询

### 4.3 实现新增角色

```
import type {
  CreateRoleInput,
  UpdateRoleInput,
} from "./schemas";

export async function createRole(
  input: CreateRoleInput
): Promise<RoleOperationResult> {
  try {
    await db.role.create({
      data: {
        code: input.code,
        name: input.name,
        description: input.description,
        isSystem: false,
        isActive: true,
      },
    });

    return { success: true };
  } catch (error) {
    if (getErrorCode(error) === "P2002") {
      return {
        success: false,
        code: "CODE_TAKEN",
        message: "角色编码已经存在",
      };
    }

    throw error;
  }
}
```

新增角色时，`isSystem` 固定为 `false`，`isActive` 固定为 `true`。

前端不能决定自己创建的是不是系统角色。

### 4.4 实现角色编辑

```
export async function updateRole(
  id: string,
  input: UpdateRoleInput
): Promise<RoleOperationResult> {
  try {
    await db.role.update({
      where: { id },
      data: {
        name: input.name,
        description: input.description,
      },
    });

    return { success: true };
  } catch (error) {
    if (getErrorCode(error) === "P2025") {
      return {
        success: false,
        code: "NOT_FOUND",
        message: "角色不存在或已被删除",
      };
    }

    throw error;
  }
}
```

这里刻意不更新 `code` 和 `isSystem`。

即使客户端自行构造请求，也无法通过这个 Service 修改角色编码或将自定义角色变成系统角色。

### 4.5 实现角色启停用

```
export async function setRoleStatus(
  id: string,
  isActive: boolean
): Promise<RoleOperationResult> {
  const role = await db.role.findUnique({
    where: { id },
    select: {
      id: true,
      isSystem: true,
    },
  });

  if (!role) {
    return {
      success: false,
      code: "NOT_FOUND",
      message: "角色不存在或已被删除",
    };
  }

  if (role.isSystem && !isActive) {
    return {
      success: false,
      code: "SYSTEM_ROLE",
      message: "系统角色不允许停用",
    };
  }

  await db.role.update({
    where: { id },
    data: { isActive },
  });

  return { success: true };
}
```

注意，这里必须在 Service 中检查系统角色，而不是只在页面上隐藏停用按钮。

真正的业务规则应该由服务端保证，前端只负责提供交互。

## 五、实现 Server Actions

Service 负责数据库操作，Server Action 负责接收表单、校验输入、调用 Service，并处理页面缓存和跳转。

创建 `features/roles/actions.ts`：

```
"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

import { requireUserAdmin } from "@/lib/auth-guard";

import {
  createRoleSchema,
  updateRoleSchema,
  type RoleFormState,
} from "./schemas";

import {
  createRole,
  updateRole,
  setRoleStatus,
} from "./service";

export async function createRoleAction(
  _prevState: RoleFormState,
  formData: FormData
): Promise<RoleFormState> {
  await requireUserAdmin();

  const values = {
    code: String(formData.get("code") ?? ""),
    name: String(formData.get("name") ?? ""),
    description: String(formData.get("description") ?? ""),
  };

  const parsed = createRoleSchema.safeParse(values);

  if (!parsed.success) {
    return {
      message: "请检查表单内容",
      fieldErrors: parsed.error.flatten().fieldErrors,
      values,
    };
  }

  const result = await createRole(parsed.data);

  if (!result.success) {
    return {
      message: result.message,
      fieldErrors:
        result.code === "CODE_TAKEN"
          ? { code: [result.message] }
          : undefined,
      values,
    };
  }

  revalidatePath("/admin/roles");
  redirect("/admin/roles?created=1");
}

export async function updateRoleAction(
  id: string,
  _prevState: RoleFormState,
  formData: FormData
): Promise<RoleFormState> {
  await requireUserAdmin();

  const values = {
    name: String(formData.get("name") ?? ""),
    description: String(formData.get("description") ?? ""),
  };

  const parsed = updateRoleSchema.safeParse(values);

  if (!parsed.success) {
    return {
      message: "请检查表单内容",
      fieldErrors: parsed.error.flatten().fieldErrors,
      values,
    };
  }

  const result = await updateRole(id, parsed.data);

  if (!result.success) {
    return {
      message: result.message,
      values,
    };
  }

  revalidatePath("/admin/roles");
  redirect("/admin/roles?updated=1");
}

export async function setRoleStatusAction(
  id: string,
  isActive: boolean
) {
  await requireUserAdmin();

  if (typeof isActive !== "boolean") {
    return {
      success: false,
      message: "无效的角色状态",
    };
  }

  const result = await setRoleStatus(id, isActive);

  revalidatePath("/admin/roles");

  return result;
}
```

这里有三个 Action：

- `createRoleAction`：创建角色。
- `updateRoleAction`：更新角色基本信息。
- `setRoleStatusAction`：启用或停用角色。

新增和编辑使用 `useActionState`，因此 Action 需要接收上一次状态和 FormData。

启停用是独立操作，不需要表单状态，直接返回操作结果即可。

## 六、实现角色表单

创建 `features/roles/components/role-form.tsx`。

本项目当前使用的表单组件是 `Input`、`Label` 和 `Button`，本篇说明字段时直接使用现有组件，不额外引入未在项目中确认的 UI 组件。

```
"use client";

import { useActionState } from "react";

import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";

import {
  createRoleAction,
  updateRoleAction,
} from "../actions";

import type { RoleFormState } from "../schemas";

type RoleFormProps = {
  role?: {
    id: string;
    code: string;
    name: string;
    description: string | null;
  };
};

const initialState: RoleFormState = {};

export function RoleForm({ role }: RoleFormProps) {
  const action = role
    ? updateRoleAction.bind(null, role.id)
    : createRoleAction;

  const [state, formAction, pending] = useActionState(
    action,
    initialState
  );

  const codeError = state.fieldErrors?.code?.[0];
  const nameError = state.fieldErrors?.name?.[0];
  const descriptionError = state.fieldErrors?.description?.[0];

  return (
    <form action={formAction} className="space-y-4">
      {!role && (
        <div className="space-y-2">
          <Label htmlFor="code">角色编码</Label>

          <Input
            id="code"
            name="code"
            defaultValue={state.values?.code}
            placeholder="例如 COURSE_MANAGER"
            aria-invalid={!!codeError}
            required
          />

          {codeError && (
            <p className="text-sm text-destructive">
              {codeError}
            </p>
          )}

          <p className="text-xs text-muted-foreground">
            创建后不可修改，建议使用大写英文和下划线。
          </p>
        </div>
      )}

      {role && (
        <div className="space-y-2">
          <Label>角色编码</Label>
          <Input value={role.code} disabled />
        </div>
      )}

      <div className="space-y-2">
        <Label htmlFor="name">角色名称</Label>

        <Input
          id="name"
          name="name"
          defaultValue={state.values?.name ?? role?.name}
          placeholder="请输入角色名称"
          aria-invalid={!!nameError}
          required
        />

        {nameError && (
          <p className="text-sm text-destructive">
            {nameError}
          </p>
        )}
      </div>

      <div className="space-y-2">
        <Label htmlFor="description">角色说明</Label>

        <Input
          id="description"
          name="description"
          defaultValue={
            state.values?.description ?? role?.description ?? ""
          }
          placeholder="描述该角色负责的业务范围"
          aria-invalid={!!descriptionError}
        />

        {descriptionError && (
          <p className="text-sm text-destructive">
            {descriptionError}
          </p>
        )}
      </div>

      {state.message && (
        <p role="alert" className="text-sm text-destructive">
          {state.message}
        </p>
      )}

      <Button type="submit" disabled={pending}>
        {pending
          ? "正在保存..."
          : role
            ? "保存修改"
            : "创建角色"}
      </Button>
    </form>
  );
}
```

这里通过 `role` 是否存在来区分新增和编辑：

```
const action = role
  ? updateRoleAction.bind(null, role.id)
  : createRoleAction;
```

新增时没有 `role`，调用创建 Action；编辑时传入角色对象，绑定角色 ID 后调用更新 Action。

`useActionState` 会根据提交结果更新表单状态。校验失败时，服务端返回错误信息和用户输入的值，页面不需要自己编写重复的校验逻辑。

## 八、实现角色启停用操作

接下来修改角色列表，让用户可以直接启用或停用角色。

创建 `features/roles/components/role-status-action.tsx`：

```
"use client";

import { useTransition } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { setRoleStatusAction } from "../actions";

type Props = {
  roleId: string;
  isActive: boolean;
  isSystem: boolean;
};

export function RoleStatusAction({
  roleId,
  isActive,
  isSystem,
}: Props) {
  const [pending, startTransition] = useTransition();

  const nextStatus = !isActive;

  function handleClick() {
    startTransition(async () => {
      try {
        const result = await setRoleStatusAction(
          roleId,
          nextStatus
        );

        if (result.success) {
          toast.success(
            nextStatus ? "角色已启用" : "角色已停用"
          );
        } else {
          toast.error(result.message ?? "操作失败");
        }
      } catch {
        toast.error("操作失败，请稍后重试");
      }
    });
  }

  return (
    <Button
      size="sm"
      variant="outline"
      disabled={pending || (isSystem && isActive)}
      onClick={handleClick}
    >
      {pending
        ? "处理中..."
        : isActive
          ? "停用"
          : "启用"}
    </Button>
  );
}
```

这里系统角色在启用状态时，停用按钮不可用。

不过，前端禁用按钮只是交互层面的保护。真正的保护仍然是 Service 中的 `isSystem` 判断。

## 十、在 Seed 中增加自定义角色数据

为了验证新增角色以外的列表场景，我们还可以在 `prisma/seed.ts` 中增加两个演示角色。

找到第12篇增加的 `seedRoles()`，在角色数组中追加：

```
{
  code: "COURSE_OPERATOR",
  name: "课程运营",
  description: "负责课程配置和课程内容维护",
  isSystem: false,
},
{
  code: "STUDENT_MANAGER",
  name: "学员管理员",
  description: "负责学员资料和学习档案管理",
  isSystem: false,
},
```

原来的 `upsert` 逻辑保持不变：

```
for (const role of roles) {
  await db.role.upsert({
    where: {
      code: role.code,
    },
    update: {
      name: role.name,
      description: role.description,
      isSystem: role.isSystem,
    },
    create: role,
  });
}
```

注意：不要在 `update` 中强制设置 `isActive: true`。

否则每次运行 Seed，之前手动停用的角色又会被重新启用。对于已经存在的数据，Seed 应该尽量只更新初始化所需的字段，避免覆盖用户在系统中的实际操作。

执行：

```
pnpm db:seed
```

这样就有了系统角色和自定义角色两类数据，可以验证不同角色的操作规则。

## 十二、本节总结

本篇完成了角色管理从只读列表到基本维护的升级。

现在角色模块具备：

- 角色新增。
- 角色名称和说明编辑。
- 角色启用与停用。
- 角色编码唯一性校验。
- 系统角色保护。
- 服务端数据校验和业务规则控制。

这里有一个值得注意的架构问题：

角色启用状态与用户账号启用状态不是一回事。

用户停用，意味着这个账号不能正常登录；角色停用，意味着这个角色不应该继续提供授权能力。一个用户可能拥有多个角色，因此不能因为某个角色被停用，就直接停用用户账号。

本篇虽然增加了 `isActive`，但还没有让它真正参与权限判断。下一篇应该解决用户与角色之间的关联管理：给用户分配角色、移除角色，并且在用户详情中查看当前拥有的角色。

这样，我们就能从“角色可以维护”进一步走向“用户通过角色获得系统能力”。
