# 第九篇：实现用户详情抽屉，让列表操作更简洁

前面几篇，我们已经完成了用户管理的主要操作：

- 用户新增
- 用户资料编辑
- 管理员重置密码
- 用户启用、停用与删除

现在回到用户管理列表，虽然功能已经比较完整，但操作区域也逐渐变得拥挤。

目前每一行用户记录后面，都有编辑、重置密码、启用/停用和删除等操作。随着功能继续增加，列表会越来越像一个操作按钮集合。

本篇我们做两项调整：

1. 增加用户详情查看功能，点击“查看”后，从页面右侧弹出抽屉，展示用户详细资料。
2. 优化列表操作区域，只保留“编辑”和“更多”两个主要入口。点击“更多”，再展示重置密码、启用/停用和删除等操作。

最终列表的操作区域变成：

```text
┌─────────────────────────────────────────────┐
│ 用户名       手机号       状态       操作    │
├─────────────────────────────────────────────┤
│ admin        138****8888  启用   查看 编辑 更多 │
│ teacher01    139****6666  启用   查看 编辑 更多 │
└─────────────────────────────────────────────┘
```

## 一、先明确本次改造的结构

本次不改变原有的业务逻辑，主要调整前端交互和用户详情查询。

涉及的文件如下：

```text
components/
└── ui/
    ├── drawer.tsx              # 新增：右侧抽屉组件
    └── dropdown-menu.tsx       # 新增：下拉菜单组件

features/
└── users/
    ├── service.ts              # 扩展用户列表查询字段
    └── components/
        ├── user-list.tsx       # 调整列表操作区域
        ├── user-detail-drawer.tsx  # 新增：用户详情抽屉
        └── user-account-actions.tsx # 改造为更多操作菜单
```

这里有一个设计原则：

**详情查看不应该变成一个新的业务修改入口。**

详情抽屉只负责读取和展示数据，编辑继续使用已有的编辑页面，重置密码、启用停用和删除继续调用原有的 Server Action。

这样可以避免为了增加一个查看功能，重复实现已有业务逻辑。

## 二、封装右侧抽屉组件

项目当前已经有 `components/ui/dialog.tsx`，它基于 `@base-ui/react/dialog` 实现。

Dialog 是居中弹窗，而我们需要的是从右侧滑出的抽屉。

这里直接复用 Base UI 的 Dialog 原语，封装一个独立的 Drawer 组件。

新建：

`components/ui/drawer.tsx`

```tsx
"use client";

import * as React from "react";
import { Dialog as DialogPrimitive } from "@base-ui/react/dialog";
import { XIcon } from "lucide-react";

import { Button } from "@/components/ui/button";
import { cn } from "cn";

function Drawer(props: DialogPrimitive.Root.Props) {
  return <DialogPrimitive.Root data-slot="drawer" {...props} />;
}

function DrawerTrigger(props: DialogPrimitive.Trigger.Props) {
  return <DialogPrimitive.Trigger data-slot="drawer-trigger" {...props} />;
}

function DrawerPortal(props: DialogPrimitive.Portal.Props) {
  return <DialogPrimitive.Portal data-slot="drawer-portal" {...props} />;
}

function DrawerClose(props: DialogPrimitive.Close.Props) {
  return <DialogPrimitive.Close data-slot="drawer-close" {...props} />;
}

function DrawerOverlay({
  className,
  ...props
}: DialogPrimitive.Backdrop.Props) {
  return (
    <DialogPrimitive.Backdrop
      data-slot="drawer-overlay"
      className={cn(
        "fixed inset-0 z-50 bg-black/30",
        "data-open:animate-in data-open:fade-in-0",
        "data-closed:animate-out data-closed:fade-out-0",
        className
      )}
      {...props}
    />
  );
}

function DrawerContent({
  className,
  children,
  showCloseButton = true,
  ...props
}: DialogPrimitive.Popup.Props & {
  showCloseButton?: boolean;
}) {
  return (
    <DrawerPortal>
      <DrawerOverlay />

      <DialogPrimitive.Popup
        data-slot="drawer-content"
        className={cn(
          "fixed inset-y-0 right-0 z-50 flex h-full w-full flex-col",
          "border-l bg-background shadow-xl",
          "sm:max-w-lg",
          "duration-300 ease-in-out",
          "data-open:animate-in data-open:slide-in-from-right",
          "data-closed:animate-out data-closed:slide-out-to-right",
          className
        )}
        {...props}
      >
        {children}

        {showCloseButton && (
          <DialogPrimitive.Close
            render={
              <Button
                variant="ghost"
                size="icon-sm"
                className="absolute right-4 top-4"
              />
            }
          >
            <XIcon />
            <span className="sr-only">关闭</span>
          </DialogPrimitive.Close>
        )}
      </DialogPrimitive.Popup>
    </DrawerPortal>
  );
}

function DrawerHeader({
  className,
  ...props
}: React.ComponentProps<"div">) {
  return (
    <div
      data-slot="drawer-header"
      className={cn("flex flex-col gap-2 border-b p-6", className)}
      {...props}
    />
  );
}

function DrawerBody({
  className,
  ...props
}: React.ComponentProps<"div">) {
  return (
    <div
      data-slot="drawer-body"
      className={cn("flex-1 overflow-y-auto p-6", className)}
      {...props}
    />
  );
}

function DrawerFooter({
  className,
  ...props
}: React.ComponentProps<"div">) {
  return (
    <div
      data-slot="drawer-footer"
      className={cn("border-t p-4", className)}
      {...props}
    />
  );
}

function DrawerTitle({
  className,
  ...props
}: DialogPrimitive.Title.Props) {
  return (
    <DialogPrimitive.Title
      data-slot="drawer-title"
      className={cn("text-lg font-semibold", className)}
      {...props}
    />
  );
}

function DrawerDescription({
  className,
  ...props
}: DialogPrimitive.Description.Props) {
  return (
    <DialogPrimitive.Description
      data-slot="drawer-description"
      className={cn("text-sm text-muted-foreground", className)}
      {...props}
    />
  );
}

export {
  Drawer,
  DrawerTrigger,
  DrawerPortal,
  DrawerClose,
  DrawerContent,
  DrawerHeader,
  DrawerBody,
  DrawerFooter,
  DrawerTitle,
  DrawerDescription,
};
```

这里需要理解几个关键点。

**1. Drawer 并不是另一个完全独立的弹窗系统。**

它仍然使用 Base UI Dialog 提供的交互能力，包括：

- 遮罩层
- 焦点管理
- 键盘交互
- Escape 关闭
- 焦点恢复

我们主要改变的是 Popup 的定位和动画。

**2. 为什么使用 `fixed inset-y-0 right-0`？**

这是抽屉从右侧弹出的关键：

- `fixed`：脱离普通文档流，固定在视口中。
- `inset-y-0`：上下撑满视口。
- `right-0`：贴合视口右侧。
- `h-full`：占满可用高度。
- `sm:max-w-lg`：在较宽屏幕上限制抽屉宽度。

**3. 为什么单独提供 DrawerBody？**

详情内容可能比较长。

抽屉顶部标题和底部操作应该保持固定，只有中间内容滚动，因此使用：

```tsx
<div className="flex h-full flex-col">
  <DrawerHeader />
  <DrawerBody />
  <DrawerFooter />
</div>
```

这样不会出现整个抽屉随内容一起滚动的问题。

## 三、扩展用户列表查询字段

当前 `getUserList` 查询返回：

```tsx
select: {
  id: true,
  username: true,
  phone: true,
  status: true,
  createdAt: true,
}
```

用户详情还需要展示最后更新时间。

因此在 `features/users/service.ts` 中，为列表查询增加 `updatedAt`：

```tsx
const items = await db.user.findMany({
  where,
  select: {
    id: true,
    username: true,
    phone: true,
    status: true,
    createdAt: true,
    updatedAt: true,
  },
  orderBy: [{ createdAt: "desc" }, { id: "desc" }],
  skip: (page - 1) * pageSize,
  take: pageSize,
});
```

这里不需要额外增加一次数据库查询。

因为用户列表本身已经读取了这些用户记录，我们可以直接将详情需要的数据传递给客户端抽屉组件。

另外需要特别注意：

**不要把 `passwordHash` 加入查询结果。**

密码哈希属于认证凭证，不是用户资料。即使只是管理员查看，也没有必要将它传递到客户端。

当前用户模型已经包含 `createdAt` 和 `updatedAt`，因此这次不需要执行 Prisma Migration。

## 四、实现用户详情抽屉

新建：

`features/users/components/user-detail-drawer.tsx`

```tsx
"use client";

import { Eye } from "lucide-react";

import { Button } from "@/components/ui/button";

import {
  Drawer,
  DrawerBody,
  DrawerContent,
  DrawerDescription,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from "@/components/ui/drawer";

import { Badge } from "@/components/ui/badge";
import { USER_STATUS_LABEL } from "../constants";

type UserDetailDrawerProps = {
  user: {
    id: string;
    username: string;
    phone: string | null;
    status: "ACTIVE" | "DISABLED";
    createdAt: Date;
    updatedAt: Date;
  };
};

const dateFormatter = new Intl.DateTimeFormat("zh-CN", {
  dateStyle: "medium",
  timeStyle: "short",
  timeZone: "Asia/Shanghai",
});

function DetailItem({
  label,
  children,
}: {
  label: string;
  children: React.ReactNode;
}) {
  return (
    <div className="space-y-1">
      <p className="text-sm text-muted-foreground">{label}</p>
      <div className="text-sm font-medium">{children}</div>
    </div>
  );
}

export function UserDetailDrawer({
  user,
}: UserDetailDrawerProps) {
  const isActive = user.status === "ACTIVE";

  return (
    <Drawer>
      <DrawerTrigger
        render={
          <Button variant="ghost" size="sm">
            <Eye className="mr-1 size-4" />
            查看
          </Button>
        }
      />

      <DrawerContent>
        <DrawerHeader>
          <DrawerTitle>用户详情</DrawerTitle>
          <DrawerDescription>
            查看用户的基本资料和账号状态。
          </DrawerDescription>
        </DrawerHeader>

        <DrawerBody>
          <div className="space-y-6">
            <div className="flex items-center gap-3">
              <div className="flex size-12 items-center justify-center rounded-full bg-muted text-lg font-semibold">
                {user.username.slice(0, 1).toUpperCase()}
              </div>

              <div>
                <p className="font-semibold">{user.username}</p>
                <p className="text-sm text-muted-foreground">
                  用户账号
                </p>
              </div>
            </div>

            <div className="grid grid-cols-2 gap-5">
              <DetailItem label="用户名">
                {user.username}
              </DetailItem>

              <DetailItem label="手机号">
                {user.phone || "未填写"}
              </DetailItem>

              <DetailItem label="账号状态">
                <Badge variant={isActive ? "default" : "secondary"}>
                  {USER_STATUS_LABEL[user.status]}
                </Badge>
              </DetailItem>

              <DetailItem label="用户 ID">
                <span className="break-all">{user.id}</span>
              </DetailItem>

              <DetailItem label="创建时间">
                {dateFormatter.format(user.createdAt)}
              </DetailItem>

              <DetailItem label="最后更新时间">
                {dateFormatter.format(user.updatedAt)}
              </DetailItem>
            </div>
          </div>
        </DrawerBody>
      </DrawerContent>
    </Drawer>
  );
}
```

这里没有重新调用 Service，也没有创建 Server Action。

原因很简单：详情所需的数据已经包含在服务端查询结果中。

用户点击查看时，只是控制抽屉显示和隐藏，不需要再向服务器请求一遍相同的数据。

这也体现了 Server Component 与 Client Component 的分工：

- Server Component：负责查询数据库。
- Client Component：负责抽屉打开、关闭等交互。
- 数据通过 Props 从服务端传给客户端。

```tsx
"use client";

import * as React from "react";
import { Menu as MenuPrimitive } from "@base-ui/react/menu";

function DropdownMenu(props: MenuPrimitive.Root.Props) {

  ...props
```

这个组件只封装了当前需要的能力：

- DropdownMenuItem：菜单选项。
- DropdownMenuSeparator：分隔线。

后续其他业务模块也可以复用，不需要每个功能都重新实现菜单。

## 六、调整用户操作区域

现在开始改造原有的 `user-account-actions.tsx`。

原来这个组件直接在列表中显示启用、停用和删除按钮。

现在把它们收进“更多”菜单，并将重置密码入口也放进去。

修改：

`features/users/components/user-account-actions.tsx`

```tsx
"use client";

import { MoreHorizontal } from "lucide-react";

import { Button } from "@/components/ui/button";

import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuItem,
  DropdownMenuSeparator,
  DropdownMenuTrigger,
} from "@/components/ui/dropdown-menu";

import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@/components/ui/alert-dialog";

import { UserResetPasswordDialog } from "./user-reset-password-dialog";

import {
  setUserStatusAction,
  deleteUserAction,
} from "../actions";

type UserAccountActionsProps = {
  user: {
    id: string;
    username: string;
    status: "ACTIVE" | "DISABLED";
  };
};

export function UserAccountActions({
  user,
}: UserAccountActionsProps) {
  const nextStatus =
    user.status === "ACTIVE" ? "DISABLED" : "ACTIVE";

  const statusAction = setUserStatusAction.bind(
    null,
    user.id,
    nextStatus
  );

  const deleteAction = deleteUserAction.bind(
    null,
    user.id
  );

  const isActive = user.status === "ACTIVE";

  return (
    <DropdownMenu>
      <DropdownMenuTrigger
        render={
          <Button variant="outline" size="sm">
            <MoreHorizontal className="size-4" />
            更多
          </Button>
        }
      />

      <DropdownMenuContent align="end">
        <UserResetPasswordDialog
          user={user}
          menuItem
        />

        <DropdownMenuSeparator />

        <form action={statusAction}>
          <DropdownMenuItem
            render={<button type="submit" className="w-full text-left" />}
          >
            {isActive ? "停用账号" : "启用账号"}
          </DropdownMenuItem>
        </form>

        <DropdownMenuSeparator />

        <AlertDialog>
          <AlertDialogTrigger
            render={
              <DropdownMenuItem className="text-destructive" />
            }
          >
            删除用户
          </AlertDialogTrigger>

          <AlertDialogContent>
            <AlertDialogHeader>
              <AlertDialogTitle>
                确认删除用户？
              </AlertDialogTitle>

              <AlertDialogDescription>
                即将永久删除用户「{user.username}」。
                删除后无法恢复，请确认该用户没有需要保留的业务数据。
              </AlertDialogDescription>
            </AlertDialogHeader>

            <AlertDialogFooter>
              <AlertDialogCancel>
                取消
              </AlertDialogCancel>

              <form action={deleteAction}>
                <AlertDialogAction
                  type="submit"
                  variant="destructive"
                >
                  确认删除
                </AlertDialogAction>
              </form>
            </AlertDialogFooter>
          </AlertDialogContent>
        </AlertDialog>
      </DropdownMenuContent>
    </DropdownMenu>
  );
}
```

这里有一个需要留意的地方：重置密码和删除操作本身都带有自己的弹窗。

现在它们被放在下拉菜单内部，点击菜单项后应该关闭菜单并打开对应的弹窗。

如果实际运行时出现菜单关闭与弹窗打开的状态冲突，需要将对应弹窗提升到菜单外层，由菜单项通过受控状态触发。不要为了追求组件嵌套简洁而牺牲交互稳定性。

另外，当前 `UserResetPasswordDialog` 还没有 `menuItem` 属性，需要做一个小改造。

### 调整重置密码组件的触发入口

在 `user-reset-password-dialog.tsx` 中增加一个属性：

```tsx
type UserResetPasswordDialogProps = {
  user: {
    id: string;
    username: string;
  };
  menuItem?: boolean;
};
```

然后调整组件参数：

```tsx
export function UserResetPasswordDialog({
  user,
  menuItem = false,
}: UserResetPasswordDialogProps) {
```

将原有的 DialogTrigger 改成条件渲染：

```tsx
{menuItem ? (
  <DialogTrigger
    render={
      <button
        type="button"
        className="flex w-full items-center rounded-sm px-2 py-2 text-left text-sm outline-none hover:bg-accent"
```

- 点击“停用账号”，确认用户状态发生变化。
- 对已停用用户点击“启用账号”，确认可以恢复。
- 点击“删除用户”，确认出现二次确认弹窗。
- 取消删除，确认用户记录仍然存在。
- 确认菜单和弹窗之间没有交互冲突。

### 6. 验证权限和数据安全

本篇没有新增修改数据的业务入口，但仍然要检查：

- 详情数据只包含允许展示的字段。
- 不向客户端传递 `passwordHash`。
- 修改和删除仍由已有 Server Action 处理。
- Server Action 仍然执行管理员守卫。
- 停用账号仍然只修改状态，不改变用户其他资料。

## 九、本篇小结

本篇主要完成了用户管理页面的交互优化。

从最初的多个按钮平铺，到现在的三个清晰入口：

- 查看：通过右侧抽屉快速查看用户资料。
- 编辑：进入独立编辑页面修改用户信息。
- 更多：将低频操作收纳到下拉菜单。

这看起来只是一次 UI 调整，但背后涉及了几个值得掌握的开发知识：

1. 基于 Base UI Dialog 封装业务通用抽屉组件。
2. 使用 Server Component 查询数据，再通过 Props 传递给 Client Component。
3. 使用 DropdownMenu 收纳低频操作。
4. 通过组件组合复用已有的密码重置、状态修改和删除功能。
5. 区分只读详情与业务修改操作，避免重复实现业务逻辑。

还有一个值得注意的设计原则：

**列表是工作入口，详情是信息窗口，编辑是业务操作，更多是辅助操作。**

当一个系统的功能逐渐增加时，不应该简单地在页面上不断堆叠按钮，而应该根据用户的操作频率和业务重要性，重新组织交互结构。
