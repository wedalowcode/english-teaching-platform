# 第五篇：实现用户新增，打通表单提交与数据库写入

## 一、前言：本篇要实现什么？

本篇实现管理员新增用户：填写用户名、手机号和初始密码，提交后完成服务端校验、密码哈希、数据库写入，并返回用户列表。

这里先处理一个安全问题：第四篇已经说明，Server Action 本质上是可被直接请求的服务端入口，不能因为按钮只对管理员显示，就认为操作安全。

目前项目还没有登录和角色权限体系，因此先增加一个**开发环境守卫**：只有 `development` 环境允许执行新增操作。等后续完成登录后，再将它替换为真正的管理员身份校验。

本篇不修改 Prisma Schema，继续使用现有 User 模型。

## 二、安装依赖

使用成熟的 Argon2 库处理密码，不再自行拼接密码哈希格式。

```bash
pnpm add argon2
pnpm approve-builds
pnpm dlx shadcn@latest add label
```

`argon2` 是原生模块，需要在安装时编译 C++ 代码。pnpm 10 之后出于安全考虑，默认不执行第三方包的构建脚本，安装时会提示 `Ignored build scripts: argon2`。执行 `pnpm approve-builds`，在交互列表里勾选 `argon2` 后回车即可放行；否则运行时会报找不到 `argon2.node` 一类的错误。

如果环境里已经装过 `argon2` 却被跳过了构建，可以执行 `pnpm rebuild argon2` 单独重编译，效果与放行构建相同，不必重装。

验证是否正常：

```bash
node -e "require('argon2').hash('test').then(h => console.log(h.slice(0, 9)))"
```

输出以 `$argon2id` 开头，说明原生模块已经可用。

OWASP 推荐优先使用 Argon2id，最低配置为内存 19 MiB、迭代 2 次、并行度 1。本篇采用这组配置。<https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html>

## 四、密码哈希与 Service

### 1. 新建 `lib/password.ts`

```ts
import "server-only";
import * as argon2 from "argon2";

export async function hashPassword(password: string) {
  return argon2.hash(password, {
    type: argon2.argon2id,
    memoryCost: 19456,
    timeCost: 2,
    parallelism: 1,
  });
}

export async function verifyPassword(
  password: string,
  passwordHash: string
) {
  return argon2.verify(passwordHash, password);
}
```

Argon2 会自动生成随机盐，并将算法、参数和盐等信息编码进哈希字符串。以后调整参数时，验证函数仍然可以根据历史哈希中的参数完成验证。

`verifyPassword` 也提前为下一篇登录功能做好准备。验证过程由 Argon2 库完成，不需要自己实现哈希比较。

### 2. 修改 `features/users/schemas.ts`

```ts
import { z } from "zod";

export const createUserSchema = z.object({
  username: z
    .string()
    .trim()
    .min(3, "用户名至少 3 位")
    .max(30, "用户名不能超过 30 位")
    .regex(/^[a-zA-Z0-9_]+$/, "只能使用字母、数字和下划线")
    .transform((v) => v.toLowerCase()),

  phone: z
    .string()
    .trim()
    .transform((v) => (v === "" ? null : v))
    .refine(
      (v) => v === null || /^1[3-9]\d{9}$/.test(v),
      "手机号格式不正确"
    ),

  password: z
    .string()
    .min(8, "密码至少 8 位")
    .max(128, "密码不能超过 128 位"),
});

export type CreateUserInput = z.infer<typeof createUserSchema>;

export type CreateUserState = {
  message?: string;
  fieldErrors?: Record<string, string[]>;
  values?: {
    username: string;
    phone: string;
  };
};
```

用户名统一转换为小写，避免 `Alice` 和 `alice` 因 PostgreSQL 默认区分大小写而成为两个账号。密码限制为 8～128 个字符，是本项目的输入长度约束，不是 Argon2 的算法限制。

### 3. 修改 `features/users/service.ts`

保留原来的用户列表查询，在文件中增加：

```ts
import { db } from "@/lib/db";
import { hashPassword } from "@/lib/password";
import type { CreateUserInput } from "./schemas";

export async function createUser(input: CreateUserInput) {
  const passwordHash = await hashPassword(input.password);

  try {
    return await db.user.create({
      data: {
        username: input.username,
        phone: input.phone,
        passwordHash,
      },
      select: { id: true },
    });
  } catch (error) {
    if (
      error &&
      typeof error === "object" &&
      "code" in error &&
      error.code === "P2002"
    ) {
      const target =
        "meta" in error &&
        error.meta &&
        typeof error.meta === "object" &&
        "target" in error.meta
          ? error.meta.target
          : undefined;

      const fields = Array.isArray(target)
        ? target
        : typeof target === "string"
          ? [target]
          : [];

      if (fields.includes("username")) {
        throw new Error("用户名已存在");
      }
    }

    throw error;
  }
}
```

这里不再先查询用户名是否存在，而是直接依赖数据库唯一索引。这样即使两个请求同时创建同一个用户名，也不会绕过唯一性约束。

同时只把 `id` 返回给上层，密码哈希不会进入前端。

## 五、实现 Server Action

新建 `features/users/actions.ts`：

```ts
"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";
import { requireUserAdmin } from "@/lib/auth-guard";
import { createUserSchema, type CreateUserState } from "./schemas";
import { createUser } from "./service";

export async function createUserAction(
  _prevState: CreateUserState,
  formData: FormData
): Promise<CreateUserState> {
  await requireUserAdmin();

  const values = {
    username: String(formData.get("username") ?? ""),
    phone: String(formData.get("phone") ?? ""),
  };

  const parsed = createUserSchema.safeParse(
    Object.fromEntries(formData.entries())
  );

  if (!parsed.success) {
    return {
      message: "请检查表单内容",
      fieldErrors: parsed.error.flatten().fieldErrors,
      values,
    };
  }

  try {
    await createUser(parsed.data);
  } catch (error) {
    if (
      error instanceof Error &&
      error.message === "用户名已存在"
    ) {
      return {
        message: error.message,
        fieldErrors: { username: [error.message] },
        values,
      };
    }

    throw error;
  }

  revalidatePath("/admin/users");
  redirect("/admin/users?created=1");
}
```

注意三个细节：

1. 权限守卫放在 Action 第一行，不能只依赖前端隐藏按钮。
2. 校验失败时回传用户名和手机号，不能回传密码。
3. 只有用户名唯一约束冲突才转换成业务提示，其他数据库错误继续抛出。

## 六、实现新增用户页面

新建 `features/users/components/user-create-form.tsx`：

```tsx
"use client";

import { useActionState } from "react";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";
import { createUserAction } from "../actions";
import type { CreateUserState } from "../schemas";

const initialState: CreateUserState = {};

export function UserCreateForm() {
  const [state, action, pending] = useActionState(
    createUserAction,
    initialState
  );

  const usernameError = state.fieldErrors?.username?.[0];
  const phoneError = state.fieldErrors?.phone?.[0];
  const passwordError = state.fieldErrors?.password?.[0];

  return (
    <form action={action} className="space-y-4">
      <div className="space-y-2">
        <Label htmlFor="username">用户名</Label>
        <Input
          id="username"
          name="username"
          defaultValue={state.values?.username}
          aria-invalid={!!usernameError}
          aria-describedby={usernameError ? "username-error" : undefined}
          required
        />
        {usernameError && (
          <p id="username-error" className="text-sm text-destructive">
            {usernameError}
          </p>
        )}
      </div>

      <div className="space-y-2">
        <Label htmlFor="phone">手机号</Label>
        <Input
          id="phone"
          name="phone"
          defaultValue={state.values?.phone}
          aria-invalid={!!phoneError}
          aria-describedby={phoneError ? "phone-error" : undefined}
        />
        {phoneError && (
          <p id="phone-error" className="text-sm text-destructive">
            {phoneError}
          </p>
        )}
      </div>

      <div className="space-y-2">
        <Label htmlFor="password">初始密码</Label>
        <Input
          id="password"
          name="password"
          type="password"
          autoComplete="new-password"
          aria-invalid={!!passwordError}
          aria-describedby={passwordError ? "password-error" : undefined}
          required
        />
        {passwordError && (
          <p id="password-error" className="text-sm text-destructive">
            {passwordError}
          </p>
        )}
      </div>

      {state.message && (
        <p role="alert" className="text-sm text-destructive">
          {state.message}
        </p>
      )}

      <Button type="submit" disabled={pending}>
        {pending ? "正在创建..." : "创建用户"}
      </Button>
    </form>
  );
}
```

用户名和手机号通过 `defaultValue` 回填，密码不回填。使用 `Label` 关联输入框，并通过 `aria-invalid`、`aria-describedby` 让辅助技术能够识别错误信息。

第四篇把查询、搜索框、表格和分页都合并进了 `UserList`，所以这一节的改动分在两个文件：成功提示进 `UserList`，入口按钮进 `page.tsx`。

### 2. 页面增加新增入口

`app/(dashboard)/admin/users/page.tsx` 完整代码如下，直接整体替换文件内容：

```tsx
import Link from "next/link";
import { Suspense } from "react";
import { buttonVariants } from "@/components/ui/button";
import {
  UserList,
  UserListSkeleton,
} from "@/features/users/components/user-list";

type Props = {
  searchParams: Promise<Record<string, string | string[] | undefined>>;
};

export default function UsersPage({ searchParams }: Props) {
  return (
    <main className="space-y-4 p-6">
      <div className="flex items-center justify-between">
        <h1 className="text-xl font-semibold">用户管理</h1>
        <Link href="/admin/users/new" className={buttonVariants()}>
          新增用户
        </Link>
      </div>

      <Suspense fallback={<UserListSkeleton />}>
        <UserList searchParams={searchParams} />
      </Suspense>
    </main>
  );
}
```

相比第四篇的版本，这个文件只改了标题区：`h1` 外面包了一层 `justify-between` 的 flex，右侧放「新增用户」链接，页面仍然不查询数据。

几个要点：

- **`created` 放在 `UserList` 里读，而不是页面里。** 页面已经把 `searchParams` 的 Promise 交给 `UserList` 了，再在页面里 `await` 一次就失去了流式渲染的意义，同一个参数也不该读两遍。
- **`params.created === "1"` 而不是 `Boolean(params.created)`。** 类型是 `string | string[] | undefined`，用它和字符串比较，数组和 `undefined` 都自然不会相等，不需要额外判断。
- **Zod 的 `object` 会丢弃未声明的键。** `userListQuerySchema` 只声明了 `page` 和 `keyword`，所以 `created` 不会出现在 `query` 里，只能从原始 `params` 上读取。
- **`buttonVariants()` 让 `Link` 保持链接语义，同时外观是按钮。** 这样「右键新窗口打开」、浏览器的前进后退都正常，比用一个 `onClick` 跳转的按钮更可靠。
- **成功提示用 `role="status"`，表单错误用 `role="alert"`。** 两者都是无障碍播报，但 `status` 是礼貌等待，适合「创建成功」这类不需要打断用户的提示；`alert` 是立即播报，适合校验失败。
- **`created` 只用于提示，不参与查询，也不进分页参数。** 翻页或重新搜索时它会自然从 URL 中消失，提示随之收起，不需要手动清理状态。
- **这个「新增用户」按钮只是入口，不构成权限控制。** 真正拦住非开发环境的是 `actions.ts` 第一行的 `requireUserAdmin()`，页面上的按钮只是把入口摆在显眼位置。

### 3. Service 测试

新增用户的测试合并到现有 `features/users/service.test.ts`，不另外新建命名相近的文件。原文件只 Mock 了 `findMany` 和 `count`，现在要补上 `create` 和 `hashPassword`。

先把文件头部改成下面这样：

```ts
import { beforeEach, describe, expect, it, vi } from "vitest";
import { createUser, getUserList } from "./service";

const { findMany, count, create, hashPassword } = vi.hoisted(() => ({
  findMany: vi.fn(),
  count: vi.fn(),
  create: vi.fn(),
  hashPassword: vi.fn(),
}));

vi.mock("server-only", () => ({}));
vi.mock("@/lib/db", () => ({
  db: { user: { findMany, count, create } },
}));
vi.mock("@/lib/password", () => ({ hashPassword }));
```

原来的 `describe("getUserList")` 整体保留不动，在文件末尾追加：

```ts
describe("createUser", () => {
  const input = {
    username: "alice",
    phone: null,
    password: "12345678",
  };

  beforeEach(() => {
    vi.clearAllMocks();
    hashPassword.mockResolvedValue("hashed-password");
    create.mockResolvedValue({ id: "user-1" });
  });

  it("写入数据库的是哈希密码，不是明文", async () => {
    await createUser(input);

    expect(hashPassword).toHaveBeenCalledWith("12345678");
    expect(create).toHaveBeenCalledWith({
      data: {
        username: "alice",
        phone: null,
        passwordHash: "hashed-password",
      },
      select: { id: true },
    });
  });

  it("空手机号以 null 写入", async () => {
    await createUser(input);

    const args = create.mock.calls[0][0];

    expect(args.data.phone).toBeNull();
  });

  it("有手机号时原样保存", async () => {
    await createUser({ ...input, phone: "13800138000" });

    const args = create.mock.calls[0][0];

    expect(args.data.phone).toBe("13800138000");
  });

  it("用户名唯一冲突时提示用户名已存在", async () => {
    create.mockRejectedValue({
      code: "P2002",
      meta: { target: ["username"] },
    });

    await expect(createUser(input)).rejects.toThrow("用户名已存在");
  });

  it("冲突字段不是用户名时继续抛出原错误", async () => {
    const error = { code: "P2002", meta: { target: ["phone"] } };

    create.mockRejectedValue(error);

    await expect(createUser(input)).rejects.toBe(error);
  });

  it("其他数据库错误继续抛出", async () => {
    const error = new Error("connection lost");

    create.mockRejectedValue(error);

    await expect(createUser(input)).rejects.toBe(error);
  });

  it("不向调用方返回 passwordHash", async () => {
    const result = await createUser(input);

    expect(result).toEqual({ id: "user-1" });
  });
});
```

几个细节：

- **`hashPassword` 必须被 Mock。** 它真实执行一次 Argon2 需要几十毫秒，而且 `lib/password.ts` 引入了 `server-only`，在测试环境里会直接报错。Mock 掉之后，这里只验证「传给哈希函数的是明文、传给数据库的是哈希值」这一层逻辑。
- **`vi.mock("@/lib/password", () => ({ hashPassword }))` 要写在文件顶部。** `vi.mock` 会被提升到所有 import 之前，所以即使 `service.ts` 引用了真实模块，拿到的也是这里的替身。
- **`mockRejectedValue` 配合 `rejects.toThrow` / `rejects.toBe`。** 前者断言异常消息，后者断言抛出的是同一个对象，用来确认非用户名的冲突没有被吞掉。
- **两个 `describe` 各自 `beforeEach`。** `getUserList` 和 `createUser` 共用了 `vi.fn()` 实例，分开清理可以避免前一个用例的 `mockResolvedValue` 影响后一个。

真实的哈希和验证行为由上面的 `lib/password.test.ts` 覆盖，这里不重复测算法本身。
