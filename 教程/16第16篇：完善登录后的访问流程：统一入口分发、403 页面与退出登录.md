# 第16篇：完善登录后的访问流程：统一入口分发、403 页面与退出登录

上一节已经完成权限目录、超级管理员、角色授权和后台菜单权限控制。

现在访问 `/admin/users`，如果当前账号没有对应权限，系统会跳转到 `/forbidden`。

权限拦截已经生效，但整个访问流程还不完整：

- 访问 `/`，仍然显示默认开发首页。
- 登录成功后，固定跳转 `/admin/users`。
- 无权限时只能返回首页，但首页没有权限管理。
- 403 页面没有退出登录入口。

本篇将把认证、入口分发、页面授权和退出登录串成完整流程。

## 一、先明确完整访问流程

我们希望最终实现：

```text
访问网站 /
    │
    ▼
检查当前登录状态
    │
    ├── 未登录 ──────→ /login
    │
    └── 已登录
          │
          ▼
      判断入口权限
          │
          ├── portal.admin ──→ /admin
          │
          ├── portal.parent ─→ /parent
          │
          └── 无入口权限 ────→ /forbidden
```

进入后台之后：

```text
/admin
   │
   ▼
后台统一布局
   │
   ▼
检查 portal.admin
   │
   ▼
加载当前用户有权访问的菜单
   │
   ▼
访问具体业务页面
   │
   ▼
检查页面权限
   │
   ├── 有权限 ──→ 正常显示
   │
   └── 无权限 ──→ /forbidden
```

这里有三个不同层次：

- `portal.admin`：是否可以进入统一后台。
- `portal.parent`：是否可以进入家长端。
- `user.view`、`role.view` 等：是否可以使用具体功能。

不能把这三种权限混在一起。

## 二、建立统一入口分发服务

先增加一个入口判断函数。

文件：`lib/auth/portal-routing.ts`

```ts
import type { CurrentActor } from "./authorization";
import { evaluatePermission } from "./authorization";

/**
 * 根据当前用户的有效入口权限决定默认访问地址。
 *
 * 同时拥有两个入口时，优先进入统一后台。
 */
export function getPortalDestination(
  actor: CurrentActor
): "/admin" | "/parent" | null {
  if (evaluatePermission("portal.admin", actor).allowed) {
    return "/admin";
  }

  if (evaluatePermission("portal.parent", actor).allowed) {
    return "/parent";
  }

  return null;
}
```

这里不直接判断角色编码。

例如：

```ts
if (actor.activeRoleCodes.includes("ADMIN")) {
  return "/admin";
}
```

这种方式不够合理。

因为用户可能拥有多个角色，角色本身也不等于入口权限。

统一通过 `portal.admin` 和 `portal.parent` 判断，后续增加新角色时不需要修改入口分发逻辑。

## 三、把根路径 `/` 改造成入口分发器

修改现有的 `app/page.tsx`。

原来的默认开发首页不再承担应用入口职责。

```tsx
import { redirect } from "next/navigation";

import { getCurrentActor } from "@/lib/auth/current-actor";
import { getPortalDestination } from "@/lib/auth/portal-routing";

export const instant = false;

export default async function HomePage() {
  const actor = await getCurrentActor();

  // 未登录或者用户已经被禁用
  if (!actor) {
    redirect("/login");
  }

  const destination = getPortalDestination(actor);

  // 已登录，但没有任何可用入口
  if (!destination) {
    redirect("/forbidden");
  }

  redirect(destination);
}
```

现在 `/` 不再渲染业务内容，而是根据当前登录身份决定去哪里。

最终结果：

| 当前身份 | 访问 `/` |
|---|---|
| SUPER_ADMIN | `/admin` |
| BOSS | `/admin` |
| ACADEMIC | `/admin` |
| ADMIN | `/admin` |
| TEACHER | `/admin` |
| AGENT | `/admin` |
| PARENT | `/parent` |
| 已登录但无入口权限 | `/forbidden` |
| 未登录 | `/login` |

如果一个用户同时拥有后台和家长端权限，本篇暂时规定优先进入后台。未来确实存在频繁切换两个门户的业务需求时，再增加门户切换入口。

## 四、增加真正的后台首页 `/admin`

现在根路径会跳转 `/admin`，因此需要有一个真实的后台首页。

新增：

`app/(dashboard)/admin/page.tsx`

```tsx
import Link from "next/link";
import { redirect } from "next/navigation";

import { adminMenus } from "@/components/layout/menu-config";
import { getCurrentActor } from "@/lib/auth/current-actor";
import { evaluatePermission } from "@/lib/auth/authorization";

export default async function AdminHomePage() {
  const actor = await getCurrentActor();

  if (!actor) {
    redirect("/login");
  }

  const items = adminMenus.flatMap((group) =>
    group.items
      .filter((item) =>
        evaluatePermission(item.permission, actor).allowed
      )
      .map((item) => ({
        ...item,
        group: group.title,
      }))
  );

  return (
    <main className="space-y-6">
      <div>
        <h1 className="text-2xl font-semibold">
          后台工作台
        </h1>

        <p className="mt-2 text-sm text-muted-foreground">
          欢迎回来，{actor.name}
        </p>
      </div>

      {items.length > 0 ? (
        <div className="grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
          {items.map((item) => (
            <Link
              key={item.href}
              href={item.href}
              className="rounded-lg border bg-card p-5 transition-colors hover:bg-accent"
            >
              <div className="font-medium">{item.title}</div>
              <div className="mt-2 text-sm text-muted-foreground">
                {item.group}
              </div>
            </Link>
          ))}
        </div>
      ) : (
        <div className="rounded-lg border bg-card p-6 text-sm text-muted-foreground">
          当前账号尚未获得具体功能权限，请联系超级管理员配置。
        </div>
      )}
    </main>
  );
}
```

这里有一个设计细节：

`/admin` 只要求拥有 `portal.admin`。

它是统一后台的入口，不代表用户可以访问所有业务功能。

页面中的快捷入口仍然根据具体权限过滤。

如果用户只有后台入口权限，却没有任何业务功能权限，也能进入后台工作台，看到明确的提示，而不是直接被踢到 403 页面。

后台布局已经在上一节检查了 `portal.admin`，因此不需要在每个后台页面重复检查入口权限。

## 五、家长端也建立独立入口

家长端和后台是两套独立门户。

新增：

`app/(parent)/parent/layout.tsx`

```tsx
import type { ReactNode } from "react";
import { redirect } from "next/navigation";

import { checkPermission } from "@/lib/auth/authorization";

export default async function ParentLayout({
  children,
}: {
  children: ReactNode;
}) {
  const decision = await checkPermission("portal.parent");

  if (decision.reason === "UNAUTHENTICATED") {
    redirect("/login");
  }

  if (!decision.allowed) {
    redirect("/forbidden");
  }

  return (
    <div className="min-h-screen bg-background">
      {children}
    </div>
  );
}
```

新增：

`app/(parent)/parent/page.tsx`

```tsx
export default function ParentHomePage() {
  return (
    <main className="mx-auto max-w-5xl space-y-4 p-8">
      <h1 className="text-2xl font-semibold">
        家长中心
      </h1>

      <p className="text-sm text-muted-foreground">
        欢迎进入家长端，孩子的学习档案和课程报告将在后续模块中接入。
      </p>
    </main>

```

这里先建立完整的入口和布局保护，具体家长功能后续再实现。

这样 PARENT 不会被错误地导入统一后台。

## 六、统一页面权限守卫

当前 `lib/auth/authorization.ts` 已经有 `requirePagePermission`，但它在无权限时返回 `allowed: false`，需要每个页面自行处理。

本篇将它调整为统一跳转模式。

修改为：

```ts
export async function requirePagePermission(
  permissionCode: PermissionCode
) {
  const decision = await checkPermission(permissionCode);

  if (decision.reason === "UNAUTHENTICATED") {
    redirect("/login");
  }

  if (!decision.allowed || !decision.actor) {
    redirect("/forbidden");
  }

  return decision.actor;
}
```

这样所有页面都只需要声明自己需要什么权限。

```ts

```

以后每个页面都使用自己的权限编码：

```ts
await requirePagePermission("student.view");
await requirePagePermission("schedule.view");
await requirePagePermission("teachingRecord.view");
```

不再使用一个笼统的 `requireAdmin()` 保护所有管理页面。

注意：页面守卫只负责页面访问，Service 和 Server Action 仍然必须独立检查权限，不能因为页面已经校验就省略服务端操作校验。

## 七、修复登录成功后的跳转

目前 `features/auth/components/login-form.tsx` 中有：

```ts
router.replace("/admin/users");
router.refresh();
```

这是导致登录流程不够灵活的地方。

因为它默认所有用户都进入用户管理页面。

修改为：

```ts
router.replace("/");
router.refresh();
```

登录成功后统一进入 `/`，再由服务端入口分发器决定进入哪个门户。

这样：

- 超级管理员进入后台。
- 教师进入后台。
- 代理进入后台。
- 家长进入家长端。

以后增加新角色，不需要再修改登录组件。

## 八、重做 403 无权限页面

这是本篇最重要的用户体验调整。

403 页面不能简单提供一个返回 `/` 的链接。

因为用户可能根本没有任何门户权限，返回 `/` 后又会重新跳回 `/forbidden`。

我们应该根据用户实际拥有的入口权限，决定是否显示返回按钮。

修改：

`app/forbidden/page.tsx`

```tsx
import Link from "next/link";
import { redirect } from "next/navigation";

import { SignOutButton } from "@/components/layout/sign-out-button";
import { getCurrentActor } from "@/lib/auth/current-actor";
import { getPortalDestination } from "@/lib/auth/portal-routing";

export const metadata = {
  title: "无权访问",
};

export default async function ForbiddenPage() {
  const actor = await getCurrentActor();

  if (!actor) {
    redirect("/login");
  }

  const destination = getPortalDestination(actor);

  return (
    <main className="flex min-h-screen items-center justify-center bg-background p-6">
      <div className="w-full max-w-md space-y-5 rounded-xl border bg-card p-8 text-center shadow-sm">
        <h1 className="text-2xl font-bold">
          无权访问
        </h1>

        <p className="text-sm text-muted-foreground">
          当前账号没有访问该页面的权限，请联系超级管理员。
        </p>

        {destination ? (
          <Link
            href={destination}
            className="inline-flex h-10 items-center justify-center rounded-md bg-primary px-4 text-sm font-medium text-primary-foreground"
          >
            返回可访问工作台
          </Link>
        ) : (
          <p className="text-sm text-muted-foreground">
            当前账号没有已授权的系统入口。
          </p>
        )}

        <div className="flex justify-center">
          <SignOutButton showLabel />
        </div>
      </div>
    </main>
  );
}
```

现在出现 403 时：

- 有后台入口权限：返回 `/admin`。
- 只有家长端入口权限：返回 `/parent`。
- 两个入口都没有：不显示返回按钮。
- 无论哪种情况，都可以退出登录。

这就解决了原来无法退出登录的问题。

## 九、完善退出登录按钮

当前项目已经有 `components/layout/sign-out-button.tsx`，并且使用 Better Auth 的 `authClient.signOut()`。

保留原有实现，只增加一个显示文字的选项。

```tsx
"use client";

import { LogOut } from "lucide-react";
import { useRouter } from "next/navigation";
import { useState } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { authClient } from "@/lib/auth-client";

type Props = {
  showLabel?: boolean;
};

export function SignOutButton({
  showLabel = false,
}: Props) {
  const router = useRouter();
  const [loading, setLoading] = useState(false);

  async function handleSignOut() {
    setLoading(true);

    try {
      const result = await authClient.signOut();

      if (result.error) {
        toast.error("退出登录失败，请重试");
        return;
      }

      router.replace("/login");
      router.refresh();
    } finally {
      setLoading(false);
    }
  }

  return (
    <Button
      variant="ghost"
      size={showLabel ? "default" : "icon-sm"}
      onClick={handleSignOut}
      disabled={loading}
      aria-label="退出登录"
    >
      <LogOut />
      {showLabel && <span>退出登录</span>}
    </Button>
  );
}
```

现在：

- 后台顶部栏继续使用图标按钮。
- 403 页面使用带文字的退出登录按钮。

退出登录由 Better Auth 清除当前会话，不能只通过跳转登录页面来模拟退出。

## 十、本篇测试清单

完成代码后，按照以下流程逐一验证。

| 测试场景 | 预期结果 |
|---|---|
| 未登录访问 `/` | 跳转 `/login` |
| SUPER_ADMIN 访问 `/` | 跳转 `/admin` |
| BOSS 访问 `/` | 跳转 `/admin` |
| TEACHER 访问 `/` | 跳转 `/admin` |
| PARENT 访问 `/` | 跳转 `/parent` |
| 已登录但没有入口权限 | 跳转 `/forbidden` |
| 已登录访问 `/login` | 跳转自己的门户 |
| 无权访问 `/admin/users` | 跳转 `/forbidden` |
| 403 页面点击返回工作台 | 进入自己有权访问的入口 |
| 403 页面点击退出登录 | 清除会话并进入 `/login` |
| 退出后重新访问 `/admin` | 跳转 `/login` |
| 没有用户管理权限但有后台入口 | 可以进入 `/admin`，不能访问用户管理 |
| 只有家长端权限 | 不能进入统一后台 |

还要重点验证：

**没有入口权限的用户进入 `/forbidden` 后，不能因为点击返回首页而陷入循环，同时必须能够退出登录。**

## 十一、本篇完成后的整体流程

```text
                  用户访问网站
                       │
                       ▼
                    根路径 /
                       │
                 获取 CurrentActor
                       │
            ┌──────────┴──────────┐
            │                     │
          未登录                已登录
            │                     │
            ▼                     ▼
         /login              判断入口权限
                                  │
                     ┌────────────┼────────────┐
                     │            │            │
                 portal.admin portal.parent   无权限
                     │            │            │
                     ▼            ▼            ▼
                  /admin       /parent      /forbidden
                     │            │            │
                     ▼            ▼            ├── 返回可访问入口
                  后台布局      家长布局       └── 退出登录
                     │
                     ▼
                 页面权限检查
                     │
              ┌──────┴──────┐
              │             │
            通过          不通过
              │             │
              ▼             ▼
           业务页面       /forbidden
```

本篇完成之后，系统就不再是简单地保护几个后台页面，而是有了一条完整的访问链路：

**登录认证 → 身份识别 → 门户分发 → 入口授权 → 页面授权 → 退出登录。**

后续新增业务模块时，只需要继续声明对应的页面权限和操作权限，不需要重新设计整个登录访问流程。
