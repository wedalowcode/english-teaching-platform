# 第十篇：搭建后台管理系统整体框架，实现左侧导航与右侧工作区

前面几篇，我们一直在实现用户管理模块。

从用户列表、用户新增、编辑、重置密码，到启用、停用、删除和详情查看，已经完成了一组比较完整的用户管理功能。

但现在有一个明显的问题：每个页面都是独立存在的。

打开用户列表，看到的是用户列表；进入编辑页面，又是另一套页面。如果继续增加角色管理、权限管理、学员管理、教师管理等功能，就会出现大量重复的页面结构。

现代后台管理系统通常不会这样设计。

不管进入哪个业务模块，页面都会保留统一的导航和操作区域，只有中间的业务内容发生变化。

本篇就来实现整个系统的通用框架。

最终效果参考项目原型：

`prototype/admin/system.html`

## 一、先看原型，明确整体布局

原型采用经典的后台管理系统布局：

```text
┌──────────────┬───────────────────────────────────────────┐
│              │ 机构名称       当前角色       消息   用户  │
│              ├───────────────────────────────────────────┤
│              │                                           │
│  系统 LOGO   │  页面标题                                  │
│              │  页面说明                                  │
│              │                                           │
│  工作台      │  ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│  经营概览    │  │ 统计卡片 │ │ 统计卡片 │ │ 统计卡片 │   │
│              │  └──────────┘ └──────────┘ └──────────┘   │
│  招生管理    │                                           │
│  客户线索    │  ┌───────────────────────────────────────┐│
│  代理管理    │  │                                       ││
│              │  │             页面业务内容              ││
│  教学管理    │  │                                       ││
│  学员管理    │  │                                       ││
│  教师管理    │  │                                       ││
│              │  └───────────────────────────────────────┘│
│  系统设置    │                                           │
│              │                                           │
└──────────────┴───────────────────────────────────────────┘
```

整体分为三个部分：

**1. 左侧导航 Sidebar**

负责展示系统品牌、业务模块和菜单。

菜单按照业务领域分组，例如：

- 工作台
- 招生管理
- 教学管理
- 排课管理
- 财务管理
- 资源中心
- 系统设置

**2. 顶部导航 Topbar**

负责展示当前机构、登录身份、消息入口和用户信息。

**3. 右侧内容区 Content**

这是整个系统真正的业务工作区。

不同路由对应不同的页面，但页面都在同一个内容框架内呈现。

例如：

```text
/admin/users
/admin/roles
/admin/students
/admin/teachers
/admin/system
```

这些页面共享同一套布局。

## 二、先确定视觉设计规范

你给的原型采用了深色侧边栏和蓝色主色调。我们继续沿用这个方向，但需要把颜色层次设计得更清楚。

我不建议整个系统都使用浅灰色背景、灰色边框和灰色文字。这样虽然看起来简洁，但不同区域之间缺乏层次，页面容易显得平淡。

这次采用以下配色：

| 使用位置 | 颜色 | 设计目的 |
|---|---|---|
| 侧边栏 | `#101B3C` | 深海军蓝，建立导航区域的视觉识别 |
| 当前菜单 | `#1D4ED8` | 明亮蓝色，突出当前所在位置 |
| 主操作按钮 | `#2563EB` | 强调重要业务操作 |
| 页面背景 | `#F3F6FC` | 浅蓝灰，区分内容工作区 |
| 内容面板 | `#FFFFFF` | 白色，突出业务内容 |
| 标题文字 | `#172033` | 深色，保证可读性 |
| 普通文字 | `#475569` | 保持层级对比 |
| 辅助文字 | `#64748B` | 用于说明、提示 |
| 边框 | `#D9E2F0` | 明确区域边界 |
| 成功状态 | `#15803D` | 绿色 |
| 警告状态 | `#B45309` | 橙色 |
| 危险状态 | `#DC2626` | 红色 |

整体视觉关系：

```text
深色侧边栏
    ↓
蓝色菜单选中态
    ↓
白色顶部导航
    ↓
浅蓝灰内容背景
    ↓
白色业务卡片
```

这样可以让导航、操作区域和业务内容形成明显区分。

这里有一个原则：

**颜色不是装饰，而是信息层级的一部分。**

主操作应该比普通操作更突出，当前菜单应该比其他菜单更突出，危险操作应该有明确的风险提示。

## 三、建立后台布局组件

这次要实现的不是某一个页面，而是整个后台的通用布局。

目录结构调整为：

```text
app/
├── layout.tsx
├── globals.css
└── (dashboard)/
    ├── layout.tsx
    └── admin/
        ├── users/
        │   └── page.tsx
        └── roles/
            └── page.tsx

components/
├── layout/
│   ├── admin-sidebar.tsx
│   ├── admin-topbar.tsx
│   └── admin-layout.tsx
└── ui/
```

这里需要理解 Next.js App Router 的一个重要设计：

`app/(dashboard)` 中的括号表示 Route Group。

它可以帮助我们组织路由结构，但不会出现在浏览器地址中。

例如：

```text
app/(dashboard)/admin/users/page.tsx
```

实际访问地址仍然是：

```text
/admin/users
```

我们把需要使用后台框架的页面统一放进 `(dashboard)` 路由组，由它的 `layout.tsx` 统一提供页面外壳。

这样以后新增一个后台业务模块，就不需要重复编写侧边栏和顶栏。

## 五、实现左侧导航 Sidebar

新建：

`components/layout/admin-sidebar.tsx`

```tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import { adminMenus } from "./menu-config";

export function AdminSidebar() {
  const pathname = usePathname();

  function isActive(href: string) {
    if (href === "/admin") {
      return pathname === href;
    }

    return pathname === href || pathname.startsWith(`${href}/`);
  }

  return (
    <aside className="fixed inset-y-0 left-0 z-40 flex w-60 flex-col bg-[#101B3C] text-white">
      {/* 品牌区域 */}
      <div className="flex h-16 shrink-0 items-center gap-3 border-b border-white/10 px-5">
        <div className="flex size-9 items-center justify-center rounded-lg bg-blue-600 text-sm font-bold shadow-lg shadow-blue-950/30">
          EE
        </div>

        <div>
          <div className="text-sm font-semibold tracking-wide">
            英语教学平台
          </div>
          <div className="text-[10px] tracking-wider text-blue-200/60">
            TEACHING MANAGEMENT
          </div>
        </div>
      </div>

      {/* 菜单区域 */}
      <nav className="flex-1 space-y-5 overflow-y-auto px-3 py-5">
        {adminMenus.map((group) => (
          <div key={group.title}>
            <div className="mb-2 px-3 text-[11px] font-semibold tracking-widest text-slate-400">
              {group.title}
            </div>

            <div className="space-y-1">
              {group.items.map((item) => {
                const active = isActive(item.href);
                const Icon = item.icon;

                return (
                  <Link
                    key={item.href}
                    href={item.href}
                    className={[
                      "group flex h-10 items-center gap-3 rounded-lg px-3 text-[13px] transition-all",
                      active
                        ? "bg-blue-600 font-semibold text-white shadow-md shadow-blue-950/30"
                        : "text-slate-300 hover:bg-white/10 hover:text-white",
                    ].join(" ")}
                  >
                    <Icon
                      className={[
                        "size-[17px] shrink-0",
                        active
                          ? "text-white"
                          : "text-slate-400 group-hover:text-blue-200",
                      ].join(" ")}
                    />

                    <span>{item.title}</span>

                    {active && (
                      <span className="ml-auto size-1.5 rounded-full bg-white" />
                    )}
                  </Link>
                );
              })}
            </div>
          </div>
        ))}
      </nav>

      {/* 底部区域 */}
      <div className="shrink-0 border-t border-white/10 p-4">
        <div className="rounded-lg bg-white/5 px-3 py-3">
          <div className="text-xs font-medium text-white">
            英语教学管理平台
          </div>
          <div className="mt-1 text-[10px] text-slate-400">
            管理端工作空间
          </div>
        </div>
      </div>
    </aside>
  );
}
```

这里重点理解三个地方。

### 1. 为什么 Sidebar 使用 Client Component？

因为当前菜单需要根据路由变化高亮。

我们使用：

```tsx
const pathname = usePathname();
```

获取当前页面地址。

再判断菜单对应的路由是否匹配：

```tsx
pathname === href || pathname.startsWith(`${href}/`)
```

这样不仅当前页面可以高亮，详情页、编辑页等子路由也可以让所属菜单保持选中。

例如：

```text
/admin/users
/admin/users/create
/admin/users/123/edit
```

这几个页面都属于用户管理菜单。

### 2. 为什么使用 fixed？

侧边栏使用：

```tsx
fixed inset-y-0 left-0
```

固定在页面左侧，占满浏览器可视高度。

右侧主区域则通过左侧留白避开侧边栏。

这样用户滚动业务内容时，菜单不会跟着滚动。

### 3. 为什么选中菜单使用蓝色背景？

菜单高亮是整个后台框架的重要视觉反馈。

普通菜单是浅灰文字，鼠标悬停时显示半透明背景，当前菜单则使用明显的蓝色背景。

用户不用仔细阅读，就能知道自己当前处于哪个模块。

## 七、组合后台整体布局

现在 Sidebar 和 Topbar 已经有了。

接下来把它们组合起来。

新建：

`components/layout/admin-layout.tsx`

```tsx
import type { ReactNode } from "react";

import { AdminSidebar } from "./admin-sidebar";
import { AdminTopbar } from "./admin-topbar";

type AdminLayoutProps = {
  children: ReactNode;
};

export function AdminLayout({
  children,
}: AdminLayoutProps) {
  return (
    <div className="min-h-screen bg-[#F3F6FC]">
      {/* 左侧菜单 */}
      <AdminSidebar />

      {/* 右侧主工作区 */}
      <div className="ml-60 flex min-h-screen min-w-0 flex-col">
        <AdminTopbar />

        <main className="min-w-0 flex-1 p-6">
          {children}
        </main>
      </div>
    </div>
  );
}
```

这段代码是整个框架的核心。

通过：

```tsx
<div className="ml-60">
```

给右侧主区域留出 240px 的空间，正好对应 Sidebar 的宽度。

然后使用：

```tsx
<div className="flex min-h-screen flex-col">
```

让右侧主工作区形成上下结构：

- 上方 Topbar。
- 下方 Main。

Main 通过 `flex-1` 自动填充剩余空间。

以后无论打开哪个业务页面，都可以复用这个布局。

## 八、接入 Next.js Layout

打开：

`app/(dashboard)/layout.tsx`

```tsx
import type { ReactNode } from "react";

import { AdminLayout } from "@/components/layout/admin-layout";

type DashboardLayoutProps = {
  children: ReactNode;
};

export default function DashboardLayout({
  children,
}: DashboardLayoutProps) {
  return (
    <AdminLayout>
      {children}
    </AdminLayout>
  );
}
```

现在 `(dashboard)` 路由组下的页面都会自动使用统一布局。

例如：

```text
app/
└── (dashboard)/
    ├── layout.tsx
    └── admin/
        ├── users/
        │   ├── page.tsx
        │   ├── create/
        │   │   └── page.tsx
        │   └── [id]/
        │       └── edit/
        │           └── page.tsx
        ├── roles/
        │   └── page.tsx
        └── system/
            └── page.tsx
```

这些页面不需要再写 Sidebar 和 Topbar。

只需要关注自己的业务内容。

这里还有一个很重要的概念：

**Layout 是共享页面外壳，Page 是具体业务页面。**

不要把业务查询、表格、表单和复杂交互全部塞进 Layout。

Layout 只负责整体结构。

## 九、调整业务页面内容区域

框架搭好后，页面内容还需要形成统一规范。

建议每个业务页面采用以下结构：

```text
页面标题区
    ├── 面包屑
    ├── 页面标题
    ├── 页面说明
    └── 页面操作按钮

统计区域（可选）

筛选区域（可选）

业务内容区域
    ├── 表格
    ├── 卡片
    └── 其他业务组件
```

以用户管理页面为例：

```tsx
<div className="space-y-6">
  {/* 页面标题 */}
  <div className="flex items-end justify-between">
    <div>
      <div className="mb-1 text-xs text-slate-500">
        系统设置 / 用户管理
      </div>

      <h1 className="text-2xl font-bold tracking-tight text-[#172033]">
        用户管理
      </h1>

      <p className="mt-2 text-sm text-slate-500">
        管理系统用户账号、状态及登录信息。
      </p>
    </div>

    <div>
      {/* 页面操作按钮 */}
    </div>
  </div>

  {/* 业务内容 */}
  <div className="rounded-xl border border-[#D9E2F0] bg-white shadow-sm">
    {/* 用户列表 */}
  </div>
</div>
```

这里使用：

```tsx
space-y-6
```

统一控制页面模块之间的间距。

页面标题、说明和业务内容也采用统一的文字层级。

这样以后开发角色管理、学员管理和教师管理时，就不需要重新考虑页面基本结构。

- 左侧导航固定在页面左边。
- 右侧内容不会被侧边栏遮挡。
- 顶部导航固定在右侧工作区顶部。
- 页面内容区域可以正常滚动。
- 浏览器刷新后布局仍然正常。

**菜单检查**

- 菜单按业务模块分组。
- 当前用户管理菜单高亮。
- 进入用户编辑页面时，用户管理菜单仍然高亮。
- 点击其他菜单可以正常跳转。

**视觉检查**

- 深色侧边栏和白色工作区有明显对比。
- 当前菜单使用蓝色背景突出。
- 主操作按钮使用蓝色，不要全部使用灰色按钮。
- 页面标题明显高于普通说明文字。
- 卡片边框清晰，但不要使用过重的阴影。
- 普通文字和辅助文字之间有明确层级。

**回归检查**

- 用户列表依然可以正常查询。
- 新增用户正常。
- 编辑用户正常。
- 重置密码正常。
- 启用、停用和删除正常。
- 用户详情抽屉正常。

本篇只增加布局，不应该改变原有用户管理业务逻辑。

## 十一、这一篇真正解决了什么问题？

到这里，我们完成了后台管理系统的第一版整体框架。

之前每个页面都需要单独处理页面布局，现在统一交给 Next.js Layout。

这种结构的好处不仅是减少重复代码，更重要的是为后续的系统扩展建立统一标准。

后续我们开发任何业务模块，都可以沿用这套框架：

```text
用户管理
角色管理
学员管理
教师管理
代理管理
订单管理
财务管理
词库管理
```

每个模块只需要实现自己的业务内容。

当然，当前还有几个能力没有接入：

1. 菜单目前是静态配置，还没有根据角色权限动态过滤。
2. 顶部用户信息还是演示数据，还没有接入真实登录会话。
3. 移动端折叠导航还没有实现。
4. 搜索和消息入口还没有对应的业务功能。

这些能力都应该在后续对应的业务章节中逐步完成，而不是为了让框架看起来完整，就提前写出没有真实业务支撑的功能。

**一个成熟的后台系统，首先需要统一的页面框架，然后才是在框架上持续增加业务能力。**

这也是从单个 CRUD 页面走向完整业务系统的重要一步。
