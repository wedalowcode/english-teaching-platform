# 英语教学管理平台实战开发（14）：实现角色成员管理与用户分配

## 一、从角色管理延伸到成员管理

上一节已经完成了角色管理的基础功能，包括角色新增、编辑、启用和停用。

现在系统已经能够维护角色，但还缺少一个重要功能：**如何管理一个角色下有哪些用户？**

例如：

- 教务角色下面有哪些用户？
- 教师角色目前关联了多少人？
- 如何给教师角色添加一名新用户？
- 某个用户不再担任教师时，如何移除他的教师角色？

之前我们已经在用户管理中实现了“分配角色”，可以从用户出发，为一个用户分配多个角色。

本节继续完善另一个方向：从角色出发，管理角色下的用户。

最终形成两个互补的管理入口：

| 管理入口 | 操作方式 | 管理内容 |
|---|---|---|
| 用户管理 | 更多 → 分配角色 | 为当前用户分配或移除角色 |
| 角色管理 | 更多 → 分配用户 | 进入当前角色的用户列表 |

角色成员管理不采用弹窗批量勾选，而是使用独立列表页面，支持搜索、分页、添加和移除。

## 二、明确页面结构

点击角色列表中的“分配用户”，进入：

```text
/admin/roles/[roleId]/users
```

页面主要包含：

- 当前角色名称及成员数量
- 用户搜索框
- 用户列表
- 分页
- 添加用户入口
- 移除用户操作

添加用户使用独立页面：

```text
/admin/roles/[roleId]/users/add
```

只显示尚未关联当前角色的用户，支持搜索、分页和逐条添加。

这样可以避免一次性加载全部用户，也避免在一个抽屉中维护大量用户的选择状态。

## 三、Service：实现角色成员查询

本节的核心数据关系仍然是第12篇建立的 `UserRole`。

一个用户可以关联多个角色，一个角色也可以关联多个用户。

不需要修改 Prisma 数据模型。

在 `features/roles/service.ts` 中增加角色成员查询方法。

### 1. 查询角色下的用户

```ts
type RoleUsersParams = {
  roleId: string;
  page: number;
  pageSize: number;
  keyword: string;
};

export async function getRoleUsers(params: RoleUsersParams) {
  const { roleId, pageSize, keyword } = params;

  const role = await getRoleById(roleId);

  if (!role) return null;

  const where: Prisma.UserWhereInput = {
    userRoles: {
      some: { roleId },
    },
    ...(keyword
      ? {
          OR: [
            { name: { contains: keyword, mode: "insensitive" } },
            { username: { contains: keyword, mode: "insensitive" } },
            { email: { contains: keyword, mode: "insensitive" } },
          ],
        }
      : {}),
  };

  const total = await db.user.count({ where });
  const totalPages = Math.max(1, Math.ceil(total / pageSize));
  const currentPage = Math.min(Math.max(1, page), totalPages);

  const items = await db.user.findMany({
    where,
    select: {
      id: true,
      name: true,
      username: true,
      email: true,
      phone: true,
      status: true,
      createdAt: true,
    },
    orderBy: [{ createdAt: "desc" }, { id: "desc" }],
    skip: (currentPage - 1) * pageSize,
    take: pageSize,
  });

  return {
    role,
    items,
    total,
    page: currentPage,
    totalPages,
  };
}
```

这里最重要的是：

```ts
userRoles: {
  some: { roleId },
}
```

它表示只查询至少存在一条当前角色关联记录的用户。

分页仍然沿用之前用户管理和角色管理的实现方式：

1. 使用 `count` 获取总记录数。
2. 计算总页数。
3. 根据当前页和每页数量计算 `skip`。
4. 使用 `take` 限制返回记录数。

### 2. 查询尚未加入角色的用户

添加用户时，不能把已经关联当前角色的用户再次显示为候选用户。

继续在 `features/roles/service.ts` 中增加：

```ts
export async function getAvailableRoleUsers(
  params: RoleUsersParams
) {
  const { roleId, pageSize, keyword } = params;

  const where: Prisma.UserWhereInput = {
    userRoles: {
      none: { roleId },
    },
    ...(keyword
      ? {
          OR: [
            { name: { contains: keyword, mode: "insensitive" } },
            { username: { contains: keyword, mode: "insensitive" } },
            { email: { contains: keyword, mode: "insensitive" } },
          ],
        }
      : {}),
  };

  const total = await db.user.count({ where });
  const totalPages = Math.max(1, Math.ceil(total / pageSize));
  const page = Math.min(Math.max(1, params.page), totalPages);

  const items = await db.user.findMany({
    where,
    select: {
      id: true,
      name: true,
      username: true,
      email: true,
    },
    orderBy: [{ createdAt: "desc" }, { id: "desc" }],
    skip: (page - 1) * pageSize,
    take: pageSize,
  });

  return {
    items,
    total,
    page,
    totalPages,
  };
}
```

这里使用 Prisma 的 `none` 条件：

```ts
userRoles: {
  none: { roleId },
}
```

表示用户没有当前角色的关联记录。

这样添加页面只会展示符合条件的用户。

## 四、Service：实现添加和移除用户

角色成员管理不再采用全量替换方式。

例如，一个角色已经关联1000名用户，如果只想添加一名用户，就不应该先删除1000条关联记录，再重新创建1000条。

应该只操作当前用户与角色之间的关联。

继续在 `features/roles/service.ts` 中增加：

### 1. 添加用户

```ts
export async function addUserToRole(
  roleId: string,
  userId: string
) {
  const [role, user] = await Promise.all([
    db.role.findUnique({
      where: { id: roleId },
      select: { id: true },
    }),
    db.user.findUnique({
      where: { id: userId },
      select: { id: true },
    }),
  ]);

  if (!role || !user) {
    return {
      success: false as const,
      message: "角色或用户不存在",
    };
  }

  await db.userRole.upsert({
    where: {
      userId_roleId: {
        userId,
        roleId,
      },
    },
    update: {},
    create: {
      userId,
      roleId,
    },
  });

  return { success: true as const };
}
```

这里使用 `upsert`，依赖第12篇已经建立的复合唯一约束：

```prisma
@@unique([userId, roleId])
```

如果关联已经存在，执行空更新；如果不存在，则创建关联。

### 2. 移除用户

```ts
export async function removeUserFromRole(
  roleId: string,
  userId: string
) {
  await db.userRole.deleteMany({
    where: {
      roleId,
      userId,
    },
  });

  return { success: true as const };
}
```

这里使用 `deleteMany`，即使关联已经不存在，也不会因为找不到记录而抛出异常。

注意：移除角色关联不等于删除用户账号，只会删除 `UserRole` 中对应的关联记录。

## 五、Action：提供添加和移除操作

在 `features/roles/actions.ts` 中增加：

```ts
import {
  addUserToRole,
  removeUserFromRole,
} from "./service";
```

然后增加两个 Server Action：

```ts
export async function addUserToRoleAction(
  roleId: string,
  userId: string
) {
  await requireUserAdmin();

  if (!roleId || !userId) {
    return {
      success: false,
      message: "参数不正确",
    };
  }

  const result = await addUserToRole(roleId, userId);

  revalidatePath(`/admin/roles/${roleId}/users`);
  revalidatePath("/admin/roles");
  revalidatePath("/admin/users");

  return result;
}

export async function removeUserFromRoleAction(
  roleId: string,
  userId: string
) {
  await requireUserAdmin();

  if (!roleId || !userId) {
    return {
      success: false,
      message: "参数不正确",
    };
  }

  const result = await removeUserFromRole(roleId, userId);

  revalidatePath(`/admin/roles/${roleId}/users`);
  revalidatePath("/admin/roles");
  revalidatePath("/admin/users");

  return result;
}
```

这里分别处理添加和移除，不再接收一组用户ID，也不再一次性替换整个角色的用户集合。

## 八、实现角色成员列表组件

新增 `features/roles/components/role-users-list.tsx`。

组件结构沿用第12篇、第13篇的列表实现方式：

- 搜索表单
- 总记录数
- 用户表格
- 空数据提示
- 通用分页组件

核心查询代码：

```tsx
const PAGE_SIZE = 10;

export async function RoleUsersList({
  roleId,
  searchParams,
}: {
  roleId: string;
  searchParams: Promise<
    Record<string, string | string[] | undefined>
  >;
}) {
  const params = await searchParams;
  const query = roleUsersQuerySchema.parse(params);

  const result = await getRoleUsers({
    roleId,
    page: query.page,
    pageSize: PAGE_SIZE,
    keyword: query.keyword,
  });

  if (!result) return null;

  const { items, total, page, totalPages } = result;

  return (
    <div className="space-y-4">
      <form className="flex gap-2">
        <Input
          name="keyword"
          defaultValue={query.keyword}
          placeholder="搜索姓名、用户名或邮箱"
          className="max-w-xs"
        />
        <Button type="submit">搜索</Button>
      </form>

      <p className="text-sm text-muted-foreground">
        当前角色共 {total} 位用户
      </p>

      <div className="rounded-md border bg-card">
        <Table>
          <TableHeader>
            <TableRow>
              <TableHead>姓名</TableHead>
              <TableHead>用户名</TableHead>
              <TableHead>邮箱</TableHead>
              <TableHead>手机号</TableHead>
              <TableHead>操作</TableHead>
            </TableRow>
          </TableHeader>

          <TableBody>
            {items.map((user) => (
              <TableRow key={user.id}>
                <TableCell>{user.name}</TableCell>
                <TableCell>{user.username ?? "-"}</TableCell>
                <TableCell>{user.email}</TableCell>
                <TableCell>{user.phone ?? "-"}</TableCell>
                <TableCell>
                  <RoleUserAction
                    roleId={roleId}
                    userId={user.id}
                    mode="remove"
                  />
                </TableCell>
              </TableRow>
            ))}

            {items.length === 0 && (
              <TableRow>
                <TableCell colSpan={5} className="h-24 text-center">
                  当前角色还没有关联用户
                </TableCell>
              </TableRow>
            )}
          </TableBody>
        </Table>
      </div>

      <ListPagination
        page={page}
        totalPages={totalPages}
        basePath={`/admin/roles/${roleId}/users`}
        params={{ keyword: query.keyword }}
      />
    </div>
  );
}
```

需要在文件顶部导入项目已有的 `Input`、`Button`、`Table`、`ListPagination`，以及本节的 Schema、Service 和 `RoleUserAction`。

## 十、实现添加和移除按钮

新增 `features/roles/components/role-user-action.tsx`：

```tsx
"use client";

import { useTransition } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import {
  addUserToRoleAction,
  removeUserFromRoleAction,
} from "../actions";

export function RoleUserAction({
  roleId,
  userId,
  mode,
}: {
  roleId: string;
  userId: string;
  mode: "add" | "remove";
}) {
  const [pending, startTransition] = useTransition();

  function handleClick() {
    startTransition(async () => {
      try {
        const result =
          mode === "add"
            ? await addUserToRoleAction(roleId, userId)
            : await removeUserFromRoleAction(roleId, userId);

        if (result.success) {
          toast.success(
            mode === "add" ? "用户添加成功" : "用户已移除"
          );
        } else {
          toast.error(result.message ?? "操作失败");
        }
      } catch {
        toast.error("操作失败，请稍后重试");
      }
    });
  }

  return (
    <Button
      size="sm"
      variant={mode === "remove" ? "outline" : "default"}
      disabled={pending}
      onClick={handleClick}
    >
      {pending
        ? "处理中..."
        : mode === "add"
          ? "添加"
          : "移除"}
    </Button>
  );
}
```

这里使用 `useTransition` 管理操作状态，避免用户在请求尚未完成时重复点击。

添加和移除成功后，Server Action 通过 `revalidatePath` 使相关服务端页面缓存失效，页面数据在后续导航或刷新时重新获取。

## 本节总结

第13篇完成了角色本身的管理，第14篇进一步完成角色成员的管理。

现在角色管理不再只是维护角色名称、编码和状态，还可以直接管理角色下的用户。

从整体设计来看，用户管理和角色管理形成了两个互补的入口：

- 用户管理：管理一个用户拥有哪些角色。
- 角色管理：管理一个角色包含哪些用户。

两者最终维护同一张 `UserRole` 关联表。

这也是 RBAC 管理界面的基本思路：围绕用户和角色两个核心对象，提供符合各自管理习惯的操作入口。
