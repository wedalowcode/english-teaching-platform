# 英语教学管理平台实战开发（14）：从用户和角色两个入口实现关联分配

## 一、前言

用户和角色是多对多关系：

- 一个用户可以拥有多个角色。
- 一个角色可以分配给多个用户。

管理员的操作习惯有两个方向：在用户管理中给用户分配角色，或者在角色管理中给角色分配用户。

因此，本篇不把角色分配藏在用户编辑页面，而是在两个列表的“更多”菜单中分别增加入口，通过侧边抽屉完成操作。

## 二、Service：统一维护 UserRole

修改 `features/users/service.ts`，增加角色查询和用户角色关联更新：

```ts
export async function getRoleOptions() {
  return db.role.findMany({
    select: {
      id: true,
      code: true,
      name: true,
      description: true,
    },
    orderBy: [{ isSystem: "desc" }, { name: "asc" }],
  });
}

export async function updateUserRoles(
  userId: string,
  roleIds: string[]
) {
  const ids = [...new Set(roleIds)];

  return db.$transaction(async (tx) => {
    const [user, roles] = await Promise.all([
      tx.user.findUnique({
        where: { id: userId },
        select: { id: true },
      }),
      tx.role.findMany({
        where: { id: { in: ids } },
        select: { id: true },
      }),
    ]);

    if (!user) {
      return { success: false as const, message: "用户不存在" };
    }

    if (roles.length !== ids.length) {
      return { success: false as const, message: "存在无效角色" };
    }

    await tx.userRole.deleteMany({ where: { userId } });

    if (ids.length) {
      await tx.userRole.createMany({
        data: ids.map((roleId) => ({ userId, roleId })),
      });
    }

    return { success: true as const };
  });
}
```

再增加从角色方向查询用户的方法。这里采用关键词搜索，最多返回30名用户，避免角色分配时一次加载整个用户表。

```ts
export async function getRoleUserCandidates(
  roleId: string,
  keyword: string
) {
  const [role, users] = await Promise.all([
    db.role.findUnique({
      where: { id: roleId },
      select: {
        id: true,
        userRoles: {
          select: { userId: true },
        },
      },
    }),

    db.user.findMany({
      where: keyword
        ? {
            OR: [
              { name: { contains: keyword, mode: "insensitive" } },
              { username: { contains: keyword, mode: "insensitive" } },
              { email: { contains: keyword, mode: "insensitive" } },
            ],
          }
        : {},
      select: {
        id: true,
        name: true,
        username: true,
        email: true,
      },
      orderBy: { createdAt: "desc" },
      take: 30,
    }),
  ]);

  if (!role) return null;

  return {
    assignedUserIds: role.userRoles.map((item) => item.userId),
    users,
  };
}
```

最后增加角色用户关联更新：

```ts
export async function updateRoleUsers(
  roleId: string,
  userIds: string[]
) {
  const ids = [...new Set(userIds)];

  return db.$transaction(async (tx) => {
    const [role, users] = await Promise.all([
      tx.role.findUnique({
        where: { id: roleId },
        select: { id: true },
      }),
      tx.user.findMany({
        where: { id: { in: ids } },
        select: { id: true },
      }),
    ]);

    if (!role) {
      return { success: false as const, message: "角色不存在" };
    }

    if (users.length !== ids.length) {
      return { success: false as const, message: "存在无效用户" };
    }

    await tx.userRole.deleteMany({ where: { roleId } });

    if (ids.length) {
      await tx.userRole.createMany({
        data: ids.map((userId) => ({ userId, roleId })),
      });
    }

    return { success: true as const };
  });
}
```

两个方法的核心逻辑一致：在事务中删除旧关联，再创建新关联。区别只是操作的主对象不同。

## 三、Action：分别处理两个分配入口

在 `features/users/schemas.ts` 增加：

```ts
export const userRoleAssignmentSchema = z.object({
  roleIds: z.array(z.string().min(1)).max(50),
});

export const roleUserAssignmentSchema = z.object({
  userIds: z.array(z.string().min(1)).max(5000),
});
```

在 `features/users/actions.ts` 引入两个 Service 方法和 Schema，增加三个 Action：

```ts
export async function updateUserRolesAction(
  userId: string,
  formData: FormData
) {
  await requireUserAdmin();

  const parsed = userRoleAssignmentSchema.safeParse({
    roleIds: formData.getAll("roleIds").map(String),
  });

  if (!parsed.success) {
    return { success: false, message: "角色数据格式不正确" };
  }

  const result = await updateUserRoles(userId, parsed.data.roleIds);

  revalidatePath("/admin/users");
  revalidatePath("/admin/roles");

  return result;
}

export async function getRoleUserCandidatesAction(
  roleId: string,
  keyword: string
) {
  await requireUserAdmin();

  return getRoleUserCandidates(roleId, keyword.trim().slice(0, 50));
}

export async function updateRoleUsersAction(
  roleId: string,
  formData: FormData
) {
  await requireUserAdmin();

  const parsed = roleUserAssignmentSchema.safeParse({
    userIds: formData.getAll("userIds").map(String),
  });

  if (!parsed.success) {
    return { success: false, message: "用户数据格式不正确" };
  }

  const result = await updateRoleUsers(roleId, parsed.data.userIds);

  revalidatePath("/admin/users");
  revalidatePath("/admin/roles");

  return result;
}
```

同时在文件顶部的 Service 导入中加入：

```ts

  getRoleOptions,
  updateUserRoles,
  getRoleUserCandidates,
  updateRoleUsers,
} from "./service";
```

新增 `features/users/components/user-role-assignment-sheet.tsx`，使用 Sheet 展示角色复选框。其核心交互如下：

```tsx
"use client";

import { useState, useTransition } from "react";
import { toast } from "sonner";
import { Checkbox } from "@/components/ui/checkbox";
import { Button } from "@/components/ui/button";
import {
  Sheet,
  SheetContent,
  SheetDescription,
  SheetHeader,
  SheetTitle,
} from "@/components/ui/sheet";
import { updateUserRolesAction } from "../actions";

export function UserRoleAssignmentSheet({
  open,
  onOpenChange,
  userId,
  username,
  roles,
  assignedRoleIds,
}: {
  open: boolean;
  onOpenChange: (open: boolean) => void;
  userId: string;
  username: string;
  roles: { id: string; code: string; name: string; description: string | null }[];
  assignedRoleIds: string[];
}) {
  const [selected, setSelected] = useState(assignedRoleIds);
  const [pending, startTransition] = useTransition();

  function toggle(id: string, checked: boolean) {
    setSelected((current) =>
      checked ? [...current, id] : current.filter((item) => item !== id)
    );
  }

  function save() {
    const formData = new FormData();
    selected.forEach((id) => formData.append("roleIds", id));

    startTransition(async () => {
      const result = await updateUserRolesAction(userId, formData);

      if (result.success) {
        toast.success("角色分配成功");
        onOpenChange(false);
      } else {
        toast.error(result.message ?? "分配失败");
      }
    });
  }

  return (
    <Sheet open={open} onOpenChange={onOpenChange}>
      <SheetContent side="right">
        <SheetHeader>
          <SheetTitle>分配角色</SheetTitle>
          <SheetDescription>
            为用户「{username}」选择角色。
          </SheetDescription>
        </SheetHeader>

        <div className="flex-1 space-y-4 overflow-y-auto px-6">
          {roles.map((role) => (
            <label key={role.id} className="flex items-start gap-3">
              <Checkbox
                checked={selected.includes(role.id)}
                onCheckedChange={(checked) => toggle(role.id, checked)}
              />
              <span>
                <span className="block font-medium">
                  {role.name}（{role.code}）
                </span>
                <span className="text-xs text-muted-foreground">
                  {role.description || "暂无说明"}
                </span>
              </span>
            </label>
          ))}
        </div>

        <div className="border-t p-6">
          <p className="mb-3 text-sm text-muted-foreground">
            已选择 {selected.length} 个角色
          </p>
          <Button onClick={save} disabled={pending} className="w-full">
            {pending ? "保存中..." : "保存分配"}
          </Button>
        </div>
      </SheetContent>
    </Sheet>
  );
}
```

## 五、角色管理：更多菜单增加分配用户

角色管理也采用相同交互，但用户数量可能很多，因此不能一次加载全部用户。

新增 `features/roles/components/role-account-actions.tsx`，在“更多”菜单中增加“分配用户”，点击后打开侧边抽屉。

抽屉中提供搜索框，输入姓名、用户名或邮箱后调用 `getRoleUserCandidatesAction`，最多展示30条匹配用户。管理员勾选用户后，保存时调用 `updateRoleUsersAction`。

实现时需要注意两点：

1. 抽屉首次打开时，调用查询 Action 获取 `assignedUserIds`，作为初始选择。
2. 搜索关键词变化时只刷新候选用户，不能覆盖已经勾选的 `selectedUserIds`，否则跨搜索条件选择的用户会丢失。

角色用户分配的保存逻辑与用户角色分配相同：将当前选中的用户 ID 逐个放入 `FormData`，提交给 `updateRoleUsersAction`。

最后修改 `features/roles/components/role-list.tsx`，在操作列加入：

```tsx
<RoleAccountActions
  roleId={role.id}
  roleName={role.name}
/>
```

原有编辑和角色启停用操作可以保留。建议将编辑、启停用和分配用户统一放入角色行的“更多”菜单，保持列表操作区域简洁。

## 六、测试与总结

分别从两个入口测试：

- 用户管理中给用户分配多个角色，角色管理中能看到关联用户数量变化。
- 角色管理中给角色分配多个用户，用户管理中能看到对应角色。
- 取消关联后，两个方向的数据都同步变化。
- 搜索用户后跨关键词选择，已勾选用户不能丢失。
- 空选择保存后，能够清除全部关联。
- 提交不存在的用户或角色 ID，操作失败，原有数据保持不变。
- 连续保存多次，不产生重复关联。
